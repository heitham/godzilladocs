Fan-out to multiple destinations

This recipe shows you how to route events from a single source to multiple destination connectors using Godzilla pipelines and transforms.

Overview

Fan-out is a common data architecture pattern where a single source of data needs to be synchronized to multiple destinations. Use cases include:

  • Syncing customer data to both your data warehouse and your CRM
  • Broadcasting events to multiple analytics platforms
  • Replicating data to multiple regional data stores

Architecture patterns

There are several ways to implement fan-out in Godzilla:

Pattern 1: Multiple pipelines from one source

Create separate pipelines for each destination, all reading from the same source connector. This is the simplest approach and gives you fine-grained control over each destination's configuration.

Pattern 2: Transform and split

Use a single pipeline with transform steps that duplicate or split events, routing them to different destinations based on event properties.

Pattern 3: Multiple connectors in one pipeline

Configure multiple destination connectors in a single pipeline to write to several targets simultaneously.

Implementation guide

Step 1: Choose your pattern

Consider your use case:

  • Use Pattern 1 if destinations have different transform logic or configuration
  • Use Pattern 2 if you need conditional routing based on event content
  • Use Pattern 3 if all destinations should receive identical events

Step 2: Set up your pipelines

Configure each pipeline with your source connector and the appropriate destination connector(s).

Step 3: Add transforms (if needed)

If using Pattern 2, add transform steps to your pipeline to split or duplicate events as needed.

Step 4: Monitor all destinations

Use the Godzilla monitoring dashboard to track event delivery to all destinations. Set up webhooks for each pipeline to get notified of failures.

Best practices

  • Idempotent writes: Design your destination systems to handle duplicate writes idempotently.
  • Separate concerns: Use Pattern 1 (separate pipelines) if different destinations have different SLAs or reliability requirements.
  • Transform consistently: Apply the same data transformations across all destinations to ensure consistency.
  • Monitor drift: Periodically verify that all destinations are in sync.
  • Rate limit awareness: Be mindful of rate limits when writing to multiple destinations simultaneously.

Example: Multi-destination customer sync

A common scenario is syncing customer data from your source system to multiple destinations:

  1. Create a source connector to your customer database
  2. Create Pipeline A with a data warehouse destination
  3. Create Pipeline B with a CRM destination
  4. Create Pipeline C with an analytics platform
  5. Configure webhooks to alert on any pipeline failures

Now customer updates will flow to all three systems in parallel.
