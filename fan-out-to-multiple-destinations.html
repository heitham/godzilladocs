Fan-out to multiple destinations

Often you need to send the same events to multiple systems: a data warehouse for analytics, a cache for real-time lookups, and a notification service for alerts. Rather than run separate pipelines for each destination, you can use a single fan-out pattern to send events to all of them.

The challenge

You have a source of events (orders, user signups, sensor readings) that need to arrive at multiple consumers. You want to:

  • Process events once from the source
  • Deliver them reliably to each destination
  • Avoid duplicates and ensure ordering
  • Monitor each destination separately

Approach: Fan-out with transforms

Create a single pipeline that receives events from your source, applies any shared transforms, then delivers them to each destination via a fan-out step:

{{ds:component/code-block|filename=fanout-pipeline.config.json|language=json|code={ "name": "user-events-fanout", "source": "kafka-prod", "transforms": [ { "type": "fan_out", "targets": [ { "destination": "analytics-warehouse", "transform": "SELECT * FROM $input" }, { "destination": "redis-cache", "transform": "SELECT user_id, email, status FROM $input" }, { "destination": "slack-alerts", "transform": "SELECT user_id, event_type FROM $input WHERE event_type IN ('critical', 'alert')" } ] } ] }}}

Key benefits

  • Single source of truth — one pipeline definition, one failure point to monitor.
  • Efficient — events are read from the source once and fanned out to all destinations.
  • Flexible transforms — each destination can receive a different subset or shape of the event.
  • Ordered delivery — events reach all destinations in the same order they were emitted.
Per-destination retries

If one destination fails, Godzilla retries it independently; other destinations continue receiving events. Use dead-letter queues to capture failures per destination.

Monitoring fan-out pipelines

In the Run Details page, you'll see:

  • Total events ingested — how many events the source emitted
  • Per-destination delivery — success/failure counts for each target
  • Latency breakdown — time to fan-out vs. time to each destination

Set up alerts on any destination that starts failing, so you catch issues before data gaps appear.

Fan-out limits

Most sources can fan out to 3–5 destinations efficiently. Beyond that, consider running a dedicated aggregation pipeline or splitting into multiple fan-out pipelines by event type.
