Overview

\n

Fan-out is a pattern where events from a single source connector are routed to multiple destination connectors simultaneously. This allows you to keep multiple systems in sync, create redundancy, or distribute data to specialized consumers.

\n\n

When to fan-out

\n

Fan-out is useful when you need to:

\n
    \n
  • Synchronize data across multiple systems (data warehouses, analytics platforms, CRMs)
    • \n
  • Create redundant copies for high-availability requirements
    • \n
  • Distribute data to different teams or departments
    • \n
  • Feed multiple machine learning models with the same feature data
    • \n
\n\n

Fan-out patterns

\n\n

Broadcast pattern

\n

Send identical events to all destinations. This is the simplest approach and works well when all consumers need the same data shape.

\n\n

Content-based routing

\n

Use transformations to route events to different destinations based on event content. For example, send customer events to a CRM and transaction events to a data warehouse.

\n\n

Filtered fan-out

\n

Each destination receives a filtered subset of events. Use transformation steps to filter before routing, or configure destination-specific filtering rules.

\n\n

Configuration

\n

To configure fan-out in Godzilla, simply connect the same source connector to multiple destination connectors in your pipeline topology. Godzilla will automatically fan out events to all connected destinations.

\n\n

Best practices

\n
    \n
  • Monitor each destination's health independently
    • \n
  • Use error handling and dead-letter queues to manage destination failures
    • \n
  • Consider rate limits on downstream systems when fanning out to many destinations
    • \n
  • Use transformations to normalize data to each destination's expected format
    • \n
  • Plan for ordering guarantees if consumers require event ordering
    • \n
