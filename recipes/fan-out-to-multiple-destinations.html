Overview

Many data architectures require the same events to flow to multiple downstream destinations. This could be for different analytics platforms, data warehouses, or operational systems. Godzilla makes it easy to fan out a single pipeline to multiple destinations with independent transformation rules.

Pattern

The recommended approach is to:

  1. Create a single source pipeline that reads from your data source
  2. Use transformation rules specific to each destination connector
  3. Fan out the transformed events to each destination
  4. Monitor each destination independently for failures
  5. Use event filtering to send different subsets of events to different destinations if needed

Implementation

Configure your pipeline with multiple destination connectors. Each destination can have its own transformation rules, so you can reshape, filter, and enrich events differently for each target system.

Godzilla handles retries independently for each destination, so a failure in one destination won't block delivery to others. Use the pipeline monitoring features to track the health of each destination connector.
