Fan-out to multiple destinations

Many data pipelines need to send events from a single source to multiple destinations, often with different transformations or filtering for each destination. This guide covers how to implement a fan-out pattern in Godzilla.

Overview

A fan-out architecture allows you to:

  • Read events once from a single source connector
  • Apply different transformations based on destination requirements
  • Send the transformed events to multiple destination connectors
  • Manage each destination's pipeline independently

Implementation strategy

There are two main approaches to implementing fan-out patterns:

Option 1: Multiple pipelines from the same source

Create separate pipelines for each destination, all reading from the same source connector:

  1. Create one pipeline per destination connector
  2. Configure each pipeline with the same source connector
  3. Add destination-specific transformations to each pipeline
  4. Point each pipeline to its corresponding destination

Benefits: Simple to understand and manage, each destination can have independent error handling.

Option 2: Transformations with conditional routing

Use your pipeline's transformation capabilities to route events to different destinations based on conditions:

  1. Create a single pipeline with the shared source
  2. Use transformation logic to tag events based on their destination
  3. Configure a destination connector that supports multiple output types or targets

Benefits: Single pipeline to manage, more efficient use of source connector cursors.

Scaling considerations

As the number of destinations grows, consider the following:

  • Source rate limits: Multiple pipelines reading from the same source may hit rate limits. Coordinate with your source system's rate-limit policies.
  • Event ordering: If you need strict ordering guarantees across destinations, the single-pipeline transformation approach may be more suitable.
  • Monitoring: Monitor each pipeline independently to catch failures quickly.

Example: Fan-out to database and analytics

A common pattern is to send events to both an operational database and an analytics warehouse:

  • Pipeline 1: Source → Database with full event schema
  • Pipeline 2: Source → Analytics with filtered/summarized data

Each pipeline can have different retention policies, error handling, and retry strategies tailored to its destination.
