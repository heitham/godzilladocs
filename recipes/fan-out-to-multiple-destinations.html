Fan-out to multiple destinations

In many architectures, a single incoming stream of events needs to reach several downstream systems simultaneously — for example, updating an analytical data warehouse, indexing in Elasticsearch for fast search, and notifying third-party services over webhooks.

Independent processing

Godzilla processes each destination branch independently. A slow or failing destination will not block or degrade delivery to other healthy destinations.

1. Create multiple destination connectors

First, define destination connectors for each service receiving the stream. See Connecting a data source for configuration details.

create-destinations.sh bash 
# Snowflake destination\ncurl -X POST https://api.godzilladocs.dev/v2/connectors \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -d '{\"name\":\"snowflake-warehouse\",\"type\":\"snowflake\",\"direction\":\"destination\",\"config\":{\"account\":\"...\"}}'\n\n# Elasticsearch destination\ncurl -X POST https://api.godzilladocs.dev/v2/connectors \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -d '{\"name\":\"es-search-index\",\"type\":\"elasticsearch\",\"direction\":\"destination\",\"config\":{\"endpoint\":\"https://...\"}}'

2. Define the fan-out pipeline

Create a pipeline specifying multiple destination connectors. You can optionally apply branch-specific transforms to shape the payload for each destination's schema.

pipeline-fanout.json json 
{
  \"name\": \"orders-multidest-fanout\",
  \"source_connector_id\": \"conn_pg_orders\",
  \"destinations\": [
    {
      \"connector_id\": \"conn_snowflake_warehouse\",
      \"transforms\": [
        { \"type\": \"enrich\", \"config\": { \"add_fields\": { \"layer\": \"dw\" } } }
      ]
    },
    {
      \"connector_id\": \"conn_es_search_index\",
      \"transforms\": [
        { \"type\": \"reshape\", \"config\": { \"drop\": [\"raw_sql\", \"binary_blob\"] } }
      ]
    }
  ]
}

3. Configure retry policies per destination

Different downstream engines have varying availability characteristics. Set distinct retry thresholds and dead-letter queues per branch to prevent temporary destination outages from polluting upstream buffers.

Dead-letter isolation

Dead-lettered events are recorded with the destination ID attached, allowing targeted replaying without duplicating events to already successful destinations.
