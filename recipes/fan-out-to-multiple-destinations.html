Fan-out to multiple destinations

A common pattern is to take events from a single source and deliver them to multiple destinations in parallel. This recipe shows how to set up and manage a fan-out pipeline.

Overview

Fan-out is useful when:

  • You need to synchronize data across multiple systems (e.g., data warehouse + analytics platform + CRM)
  • You want independent retry and error handling for each destination
  • You're migrating data across multiple systems simultaneously

Prerequisites

  • One source connector configured
  • Multiple destination connectors ready to receive events
  • Understanding of pipelines and how they route events

Steps

1. Create a base pipeline

Start by creating a pipeline connected to your source and one destination. Test that data flows correctly end-to-end.

2. Add additional destinations

In your pipeline configuration, add a second destination connector. Godzilla will automatically fan out events from the source to both destinations.

3. Configure independent error handling

Each destination can have its own error handling and retry policy. If one destination fails, events are still delivered to the others.

4. Monitor fan-out health

Use monitoring and alerts to track the health of each destination independently. Set up webhooks to notify your team of destination-specific failures.

5. Scale to more destinations

You can add as many destinations as needed. Each receives events in parallel, so throughput remains consistent regardless of the number of destinations.
