Backfill historical data

This recipe shows you how to load historical data into your pipeline and populate your destination with events from the past.

Overview

Backfilling is useful when you're setting up a new pipeline but need to ensure your destination has all historical data, not just future events from the moment the pipeline goes live.

Steps

1. Prepare your historical data source

Export your historical data in a format compatible with Godzilla (JSON lines, CSV, or your connector's native format). Ensure the data includes the same fields your live pipeline will receive.

2. Create or configure a batch source connector

Set up a source connector that can read your historical dataset in bulk. This might be a file-based connector, database query, or API paginator.

3. Run the backfill pipeline

Create a separate pipeline or trigger your existing pipeline with the historical data source. Monitor the pipeline to ensure all records are processed without errors.

4. Verify completeness

Once the backfill completes, compare record counts and spot-check samples in your destination to confirm all historical data was transferred.

5. Switch to the live source

Once backfilling is complete and verified, update your pipeline to use the live data source for ongoing ingestion.

Best practices

  • Run backfills during off-peak hours to minimize impact on live traffic.
  • Use idempotent transformations so backfill data can be re-ingested safely if needed.
  • Enable comprehensive logging during backfill to troubleshoot any failures.
  • Keep a record of what data was backfilled and when for audit purposes.
