Backfill historical data

When you add a new destination to an existing pipeline, you often want to load historical data from your source system into the new destination while also processing new events. This guide covers the recommended approach for implementing a data backfill.

Overview

A backfill operation involves:

  • Running a one-time data load of historical records from your source system
  • Keeping the pipeline running in parallel to process new events
  • Ensuring no events are duplicated or lost during the backfill

Recommended approach

The most reliable way to backfill historical data is to use a separate pipeline specifically for the backfill operation:

  1. Create a new pipeline with the same source connector as your production pipeline
  2. Configure the source connector to start from your backfill cutoff date or event ID
  3. Point this backfill pipeline to your new destination connector
  4. Run the backfill pipeline to completion
  5. Once complete, add the new destination to your production pipeline for handling new events

This approach ensures that your production pipeline continues uninterrupted while the backfill happens in parallel.

Handling duplicates and gaps

Be aware that events at the boundary between the backfill period and the production pipeline start may appear in both pipelines. Implement idempotency in your destination system (checking for duplicate IDs or using upsert logic) to handle any overlapping events gracefully.
