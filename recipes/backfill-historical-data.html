Overview

When connecting a new destination to an existing pipeline, you often want to load all historical data from the source system rather than starting from the current moment. This recipe shows you how to safely backfill data without disrupting your live pipeline.

Prerequisites

  • An existing pipeline with at least one source and one destination
  • Access to historical data in your source system (e.g., via batch export or time-range queries)
  • Understanding of pipeline versioning and event replay (see Handling errors & retries)

Steps

1. Pause the live pipeline

Before backfilling, pause your existing pipeline to prevent new events from being processed while you're loading historical data.

{{ds:component/code-block|filename=example.sh|language=bash|code=curl -X PATCH https://api.godzilla.io/v2/pipelines/my-pipeline \\\n -H "Authorization: Bearer YOUR_API_KEY" \\\n -d '{\"status\": \"paused\"}'}}

2. Export historical data from your source

Export all historical events from your source system. Most sources support a time-range query or batch export function. Format the data to match your pipeline's event schema.

3. Create a temporary backfill pipeline

Create a new pipeline that reads from a batch source (like a CSV upload or S3 bucket) and writes to your destination. This keeps backfill data separate from live events.

4. Verify the backfill

Confirm that all historical data has been successfully written to your destination before resuming the live pipeline.

5. Resume the live pipeline

Once backfill is complete, resume your original pipeline to continue processing new events.

{{ds:component/code-block|filename=example.sh|language=bash|code=curl -X PATCH https://api.godzilla.io/v2/pipelines/my-pipeline \\\n -H "Authorization: Bearer YOUR_API_KEY" \\\n -d '{\"status\": \"running\"}'}}

Best practices

  • Test in staging first: Always dry-run your backfill in a non-production environment
  • Monitor event ordering: If event order matters, ensure your backfill process maintains chronological order
  • Handle duplicates: Your destination should be idempotent or have deduplication logic in case of accidental replays
  • Document the backfill: Record the time range and volume of data backfilled for audit purposes
