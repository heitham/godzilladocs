Backfill historical data

\n

When building a new pipeline to a destination system, you often need to load historical data from your source in addition to new events flowing forward. This recipe shows how to backfill data alongside live event streaming.

\n\n

Overview

\n

Backfilling typically involves:

\n
    \n
  1. Setting up your connectors and pipeline for live event streaming
    2. \n
  2. Running a separate backfill process to pull historical records
    3. \n
  3. Ensuring the backfill and live pipeline don't duplicate events
    4. \n
\n\n

Setting up the pipeline

\n

First, create your source and destination connectors and activate the pipeline to start processing new events:

\n\n
\n
\n setup-pipeline.sh\n bash\n \n
\n 
curl -X POST https://api.godzilladocs.dev/v2/pipelines \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -d '{\n    \"name\": \"orders-to-warehouse\",\n    \"source_connector_id\": \"conn_postgres_orders\",\n    \"destination_connector_id\": \"conn_snowflake_warehouse\"\n  }'
\n
\n\n

Running the backfill

\n

Use your source system's native tools to extract historical data and replay it through the pipeline. For example, with Postgres:

\n\n
\n
\n backfill.sh\n bash\n \n
\n 
psql -h orders-db.example.com -U user -d orders_db -c \\\n  \"SELECT * FROM orders WHERE created_at < NOW() - interval '30 days'\" | \\\n  curl -X POST https://api.godzilladocs.dev/v2/events \\\n    -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n    -H \"Content-Type: application/json\" \\\n    -d @-
\n
\n\n

Avoiding duplicates

\n

To prevent events from appearing twice in your destination:

\n\n
\n
Use an event timestamp cutoff
\n

Query your source for records created before the pipeline was activated, then track the cutoff time. Events created after the pipeline starts will flow through live streaming; earlier events come through backfill.

\n
\n\n

If your destination supports idempotency keys, include a unique event identifier so the destination can detect and skip duplicates automatically.

\n\n

Monitoring the backfill

\n

Check backfill progress using the Events API to query how many records have made it to your destination:

\n\n
\n
\n check-progress.sh\n bash\n \n
\n 
curl https://api.godzilladocs.dev/v2/events \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -d '{\"pipeline_id\": \"pipe_orders_warehouse\", \"status\": \"delivered\"}'
