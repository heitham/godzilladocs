Backfill historical data

When you set up a new pipeline, you often want to load historical data that already exists in your source system. This recipe shows how to configure your pipeline to replay data from the past without disrupting real-time event flow.

The pattern

Backfilling typically involves two phases:

  1. Batch load: Query your source system for all historical records within a date range.
  2. Stream events: Once historical data catches up, switch to real-time event streaming for ongoing updates.

Godzilla pipelines support both approaches through the same connectors and destination configuration, so you can use one pipeline for both historical and real-time data.

Set up a source connector with a date filter

Most source connectors accept configuration options to limit which records to pull. For example, a Postgres source can query records after a specific timestamp:

backfill-source.json json 
{
  "type": "postgres",
  "direction": "source",
  "config": {
    "connection_string": "postgres://user:pass@host/db",
    "query": "SELECT * FROM events WHERE created_at >= '2024-01-01'",
    "polling_interval_seconds": 3600
  }
}

The polling_interval_seconds setting controls how often the source checks for new records. For backfill, you might use a longer interval (like 3600 seconds = 1 hour) to avoid overwhelming your source system.

Create the pipeline

Your backfill pipeline works exactly like any other pipeline. Create it using the source connector from the previous step and your destination:

create-backfill-pipeline.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/pipelines \
  -H "Authorization: Bearer $GODZILLA_API_KEY" \
  -d '{
    "name": "backfill-events",
    "source_connector_id": "conn_pg_backfill",
    "destination_connector_id": "conn_snowflake_dw"
  }'

Monitor backfill progress

Use the Pipelines endpoint to check how many events have been processed:

check-progress.sh bash 
curl -X GET https://api.godzilladocs.dev/v2/pipelines/backfill-events \
  -H "Authorization: Bearer $GODZILLA_API_KEY"

The response includes stats.events_processed and stats.events_failed so you can track progress in real time. See Monitoring & alerts to set up notifications when backfill completes.
