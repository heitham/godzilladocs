Backfill historical data

Backfilling lets you stream historical data from your storage or database into downstream targets — bootstrapping new destinations, backpopulating historical records, or replaying data after schema changes.

Before you begin

Ensure your source connector supports range queries or timestamp filtering. See Connecting a data source for connector details.

1. Define a time-bounded source connector

Configure your source connector with start and end timestamps (or watermarks) to define the historical boundary. This prevents the backfill job from processing live events prematurely.

backfill-source.json json 
{
  "type": "postgres",
  "direction": "source",
  "config": {
    "connection_string": "postgres://user:secret@db.example.com:5432/production",
    "query": "SELECT * FROM orders WHERE created_at >= '2025-01-01T00:00:00Z' AND created_at < '2026-01-01T00:00:00Z'",
    "timestamp_column": "created_at"
  }
}

2. Set batch size and concurrency controls

Historical backfills often involve large data volumes. Adjust your pipeline's batch size and concurrency limit to avoid exhausting memory or triggering rate limits on your destination system.

pipeline-backfill.json json 
{
  "name": "orders-backfill-2025",
  "source_connector_id": "conn_pg_orders_backfill",
  "destination_connector_id": "conn_snowflake_dw",
  "settings": {
    "batch_size": 5000,
    "concurrency": 4,
    "max_retries": 5
  }
}
Destination throughput

Monitor destination write latency while the backfill runs. If destination response times spike, reduce pipeline concurrency.

3. Run and monitor the backfill

Start the pipeline using the Pipelines endpoint. You can inspect event throughput and error rates via Monitoring & alerts.

run-backfill.sh bash 
curl -X POST https://api.godzilladocs.dev/v3/pipelines/orders-backfill-2025/start \
  -H "Authorization: Bearer $GODZILLA_API_KEY"

4. Transitioning to real-time streaming

Once the backfill reaches the cutoff timestamp, switch the pipeline configuration or activate your real-time streaming pipeline. Godzilla ensures idempotent writes when keys are configured, preventing duplicate entries during handoff.
