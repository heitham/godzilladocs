Pipelines endpoint v3

Create and manage pipelines programmatically. Base URL: https://api.godzilladocs.dev/v3.

Current version

v3 is the current stable release with improved error handling, execution timeouts, and better pagination. Looking for v2? It remains fully supported but no longer receives new features.

Create a pipeline

POST /v3/pipelines

Name Type Required Description
namestringYesHuman-readable pipeline name, unique per workspace.
source_connector_idstringYesID of the connector events are read from.
destination_connector_idstringYesID of the connector events are written to.
transformsarrayNoOrdered list of transform step definitions. Omit for a pass-through copy.
schedulestringNoCron expression. Omit for event-triggered (streaming) pipelines.
timeout_secondsintegerNoMaximum execution time per run. Defaults to 3600 seconds (1 hour). New in v3.
max_retriesintegerNoMaximum number of retry attempts on transient failures. Defaults to 3. New in v3.
create-pipeline.sh bash 
curl -X POST https://api.godzilladocs.dev/v3/pipelines \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"name\": \"ingest-orders\",\n    \"source_connector_id\": \"conn_pg_orders\",\n    \"destination_connector_id\": \"conn_snowflake_dw\",\n    \"timeout_seconds\": 1800,\n    \"max_retries\": 5\n  }'

What's new in v3

\n
    \n
  • Execution timeouts: Specify per-run timeout with the timeout_seconds parameter. Runs exceeding the limit are automatically terminated and retried.
    • \n
  • Improved retries: The max_retries parameter gives you fine-grained control over retry behavior for transient failures.
    • \n
  • Enhanced error responses: Error objects now include a retry_after field indicating how long to wait before retrying rate-limited requests.
    • \n
  • Better pagination: Cursor pagination now includes a has_more boolean for easier client-side logic.
    • \n
\n\n
Deleting a pipeline

Deleting a pipeline does not delete its source or destination connectors, and does not delete events already written to the destination. In-flight runs are allowed to finish before deletion completes.
