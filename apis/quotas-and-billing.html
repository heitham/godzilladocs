Quotas & billing

Your Godzilla account operates under a plan tier that defines your request quotas, concurrent connection limits, and billing model. Understanding your limits and what happens when you exceed them helps you plan infrastructure and avoid service interruption.

Plan tiers

We offer three plan tiers, each with its own quota for API requests, concurrent event streams, and stored event history:

Plan Requests/min Concurrent streams Event retention Billing
Starter 100 5 7 days Free
Standard 1,000 25 90 days $99/month
Enterprise Custom Custom Custom Custom

Upgrade to a higher tier anytime from your Account Settings page. Changes take effect immediately.

What happens when you exceed your quota

Request rate limits

When you exceed your plan's request limit, the API returns a 429 Too Many Requests response. The response includes a Retry-After header indicating how long to wait (in seconds) before retrying.

rate-limit-response.json json 
HTTP/1.1 429 Too Many Requests\nRetry-After: 60\n\n{\n  \"error\": {\n    \"code\": \"rate_limit_exceeded\",\n    \"message\": \"Request limit of 1,000 requests/minute exceeded. Retry after 60 seconds.\",\n    \"request_id\": \"req_abc123\"\n  }\n}

To handle rate limits gracefully, implement exponential backoff and respect the Retry-After header. See Handling errors & retries for patterns and code examples.

Rate limit headers

Every successful response also includes X-RateLimit-Limit (your quota), X-RateLimit-Remaining (requests left in the current window), and X-RateLimit-Reset (Unix timestamp when the window resets). Use these to anticipate rate limits before hitting them. See Rate limits & errors for details on headers.

Concurrent stream limits

Each plan tier supports a maximum number of concurrently open event streams (webhook subscriptions, polling connections, etc.). Attempts to open a stream beyond your limit return a 429 with code stream_limit_exceeded.

To resolve, either:

  • Close unused streams in your connector dashboard
  • Consolidate multiple streams into a single high-volume subscription
  • Upgrade to a higher tier

Event retention limits

Events older than your plan's retention window are automatically deleted. For example, Starter-tier events older than 7 days are purged. To preserve older events, export them to your own database or data warehouse before they expire.

No recovery after expiry

Once an event is purged from Godzilla, it cannot be recovered. Plan your export/archival strategy accordingly.

Monitor your quota usage

Check your current usage in the Dashboard → Usage section. You can see:

  • Current request count within the rolling minute window
  • Active concurrent streams
  • Event storage used vs. plan limit

Enable billing alerts in Account Settings → Notifications to receive warnings when approaching rate limits or storage capacity.

Enterprise & custom quotas

For workloads exceeding Standard-tier limits, contact sales@godzilla.dev to discuss a custom Enterprise plan. We can provision higher request rates, more concurrent streams, longer retention, and priority support.
