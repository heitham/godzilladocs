Transforms endpoint v2

Create and manage transform steps within pipelines. Transform steps are applied in order between source and destination connectors to filter, map, or enrich events.

Create a transform

POST /v2/pipelines/{pipeline_id}/transforms

Name Type Required Description
pipeline_idstringYesID of the pipeline to add the transform to.
namestringYesHuman-readable name for the transform step.
typestringYesOne of filter, map, enrich, or aggregate.
configobjectYesType-specific configuration, e.g. filter predicates or mapping rules.
positionintegerNoPosition in the transform chain. If omitted, appends to the end.

List transforms

GET /v2/pipelines/{pipeline_id}/transforms — returns an ordered array of transform steps configured for the pipeline.

Transform order and execution

Transforms are executed sequentially in the order they appear in the pipeline. Events flow left-to-right: source → transform[0] → transform[1] → ... → destination. Reorder transforms by updating a pipeline's transforms array directly.

Transform failures

If a transform step fails (e.g. due to a malformed predicate), the event is logged as an error and does not flow to the destination. Review pipeline logs for details.

Transform types

Filter

Exclude events matching a predicate. Events that do not match are passed through unchanged.

Map

Transform event fields using a mapping expression. Commonly used to rename, nest, or flatten fields.

Enrich

Add new fields to an event by joining with external data or applying a lookup.

Aggregate

Combine multiple events into a single event over a time window or count-based trigger.

Testing transforms

Test your transform configuration against sample events before deploying to a live pipeline. Use the pipeline preview endpoint to validate the transform chain end-to-end.
