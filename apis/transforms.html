Transforms endpoint v2

Define and manage transform steps that process data as it flows through a pipeline. Base URL: https://api.godzilladocs.dev/v2.

Create a transform step

POST /v2/transforms

Transform steps are ordered operations that filter, enrich, or reshape events within a pipeline. Each step receives the output of the previous step (or source events, if it is the first step) and passes the result to the next step.

Name Type Required Description
pipeline_idstringYesID of the pipeline this transform belongs to.
namestringYesHuman-readable name for this transform step.
typestringYesOne of filter, map, enrich, aggregate, or custom.
orderintegerYesPosition in the transform chain (0-based). Determines execution order.
configobjectYesType-specific configuration. See transform types below.
enabledbooleanNoWhether this step is active. Defaults to true.

Transform types

filter: Keep or discard events based on a condition.

filter-transform.json json 
{\n  "type": "filter",\n  "config": {\n    "condition": "event.amount > 100"\n  }\n}

map: Transform field names or values.

map-transform.json json 
{\n  "type": "map",\n  "config": {\n    "mappings": {\n      "order_id": "id",\n      "customer_email": "email"\n    }\n  }\n}

enrich: Add fields from an external source or computed values.

enrich-transform.json json 
{\n  "type": "enrich",\n  "config": {\n    "lookup_connector_id": "conn_pg_customers",\n    "join_key": "customer_id",\n    "fields": ["segment", "ltv"]\n  }\n}

aggregate: Combine or roll up multiple events.

aggregate-transform.json json 
{\n  "type": "aggregate",\n  "config": {\n    "window_seconds": 3600,\n    "group_by": "customer_id",\n    "aggregation": "sum"\n  }\n}

custom: User-defined logic in Python or JavaScript.

custom-transform.json json 
{\n  "type": "custom",\n  "config": {\n    "language": "javascript",\n    "code": "event.processed_at = new Date().toISOString(); return event;"\n  }\n}

Create request example

create-transform.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY" \\\n  -H "Content-Type: application/json" \\\n  -d '{\n    "pipeline_id": "pipe_ingest_orders",\n    "name": "Filter high-value orders",\n    "type": "filter",\n    "order": 0,\n    "config": {\n      "condition": "event.amount > 500"\n    }\n  }'

List transforms for a pipeline

GET /v2/pipelines/{pipeline_id}/transforms — returns all transform steps for a pipeline, ordered by the order field.

list-transforms.sh bash 
curl https://api.godzilladocs.dev/v2/pipelines/pipe_ingest_orders/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY"

Response includes an array of transform objects, each with id, name, type, order, config, enabled, created_at, and updated_at fields.

Update a transform step

PATCH /v2/transforms/{id} — modify a transform's configuration, name, or enabled status. Reordering within a pipeline requires updating multiple transform order fields atomically.

Live pipeline impact

Updating an enabled transform in an active pipeline takes effect immediately on newly ingested events. In-flight events may still use the prior transform configuration.

Transform validation

Transform configs are validated on create and update:

  • filter: Condition must be a valid expression referencing event fields.
  • map: Mapping keys must match source event schema.
  • enrich: Lookup connector must exist and the join key must be present in both the event and lookup table.
  • aggregate: Window duration must be positive; group-by field must exist.
  • custom: Code must be valid Python or JavaScript and return an object.
Transform errors in production

If a transform encounters an error at runtime (e.g., custom code throws an exception), the event is routed to your pipeline's error queue and is not delivered to the destination. Check the events endpoint for error reasons.
