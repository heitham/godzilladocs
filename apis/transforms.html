Transforms endpoint v2

Create and manage transform steps within pipelines. Transforms define how events are modified as they flow through the system. Base URL: https://api.godzilladocs.dev/v2.

Create a transform

POST /v2/pipelines/{pipeline_id}/transforms

Name Type Required Description
namestringYesHuman-readable transform name, unique within the pipeline.
typestringYesOne of map, filter, aggregate, sql, or custom.
configobjectYesType-specific configuration. For map: field mappings. For filter: predicate expression. For sql: SQL query.
positionintegerNoZero-indexed position in the transform chain. If omitted, appended to the end.
create-transform.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/pipelines/pipe_abc123/transforms \
  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \
  -H \"Content-Type: application/json\" \
  -d '{
    \"name\": \"normalize-customer-id\",
    \"type\": \"map\",
    \"config\": {
      \"mappings\": {
        \"source_field\": \"customer_id\",
        \"target_field\": \"normalized_id\",
        \"function\": \"lower\"
      }
    }
  }'

List transforms

GET /v2/pipelines/{pipeline_id}/transforms — returns all transform steps in the pipeline, ordered by position. See Rate limits & errors for the pagination envelope.

list-transforms.sh bash 
curl -X GET https://api.godzilladocs.dev/v2/pipelines/pipe_abc123/transforms \
  -H \"Authorization: Bearer $GODZILLA_API_KEY\"

Transform types

map

Rename fields and apply simple transformations (lowercase, uppercase, trim, etc.) to individual values.

filter

Exclude events that don't match a boolean condition. Useful for discarding invalid or out-of-scope records before writing to the destination.

aggregate

Combine multiple events into a single output record using a grouping key and aggregation function (sum, count, avg).

sql

Run arbitrary SQL queries against the incoming event stream. Requires the destination to support SQL execution.

custom

Execute custom JavaScript or Python code. The runtime has access to the incoming event object and must return the transformed output.

Transform order matters

Transforms are executed in position order. For example, a filter transform at position 1 will exclude events before they reach a map transform at position 2. Plan your transform chain carefully to avoid unexpected results.

Error handling

If a transform fails on a particular event, that event is moved to the pipeline's dead-letter queue (DLQ) and logged under the pipeline's error_count metric. Subsequent transforms in the chain are skipped. Use GET /v2/pipelines/{pipeline_id}/events?status=failed to inspect failures.
