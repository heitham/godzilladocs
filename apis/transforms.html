Transforms endpoint v2

Create and manage transform steps that process events within a pipeline. Transform steps define how events are filtered, mapped, aggregated, and enriched as they flow from source to destination. Base URL: https://api.godzilladocs.dev/v2.

Create a transform step

POST /v2/pipelines/{pipeline_id}/transforms

Name Type Required Description
pipeline_idstringYesID of the pipeline containing this transform step.
typestringYesOne of filter, map, aggregate, enrich, or custom.
positionintegerYesPosition in the transform pipeline (0-based, determines execution order).
configobjectYesType-specific configuration, e.g. filter expression or mapping rules.
enabledbooleanNoWhether this transform step is active. Defaults to true.
create-transform.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/pipelines/pipe_12345/transforms \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"type\": \"filter\",\n    \"position\": 0,\n    \"config\": {\n      \"expression\": \"event.amount > 100\"\n    },\n    \"enabled\": true\n  }'

List transforms in a pipeline

GET /v2/pipelines/{pipeline_id}/transforms — returns all transform steps for a pipeline, ordered by position.

list-transforms.sh bash 
curl -X GET https://api.godzilladocs.dev/v2/pipelines/pipe_12345/transforms \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\""

Transform types

filter — Remove events matching a condition. Config includes a expression (JMESPath-style query) that returns true to exclude the event.

map — Reshape or rename fields. Config includes mappings (object) where keys are destination field names and values are source expressions.

aggregate — Group events and combine them. Config includes group_by (expression) and window (time window in seconds).

enrich — Augment events with data from external sources. Config includes source_url and lookup_key.

custom — Run user-defined code (Python or JavaScript). Config includes runtime and code.

Transform execution order

Transforms execute in position order. Moving or deleting a transform step may renumber subsequent steps. Verify your pipeline logic after structural changes.

Disabling vs. deleting

Set enabled: false to skip a transform without removing it or renumbering steps. This is useful for temporary testing or gradual rollouts.
