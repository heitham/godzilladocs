Transforms endpoint v2

Manage transform steps — inline data reshaping, filtering, and enrichment operations that run on events as they flow through a pipeline.

Create a transform step

POST /v2/transforms

Name Type Required Description
pipeline_idstringYesID of the pipeline this transform belongs to.
namestringYesHuman-readable name for the transform step.
typestringYesOne of filter, map, enrich, or custom.
configobjectYesType-specific transformation logic, e.g. a filter expression or mapping template.
orderintegerYesPosition in the transform chain (0-indexed). Transforms run in ascending order.

List transform steps

GET /v2/pipelines/{pipeline_id}/transforms — returns a list of all transform steps for a given pipeline, ordered by execution order.

list-transforms.sh bash 
curl https://api.godzilladocs.dev/v2/pipelines/pipe_ingest_orders/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY"

Transform execution order

Transforms within a pipeline execute in ascending order value. When creating multiple transforms at once, assign sequential order values to ensure consistent behavior. Reordering transforms mid-pipeline does not affect events already in flight.

Order matters

Transforms are applied in sequence to each event. A filter in position 0 may prevent events from reaching an enrichment step in position 1. Plan your transform chain carefully.

Transform types

  • filter — exclude events matching a condition; dropped events are counted separately and not written to the destination.
  • map — reshape event fields using a template; useful for normalizing source formats to match destination schema.
  • enrich — fetch and merge external data into events; requires connectors with catalog support.
  • custom — run user-supplied JavaScript or SQL logic; incurs additional latency.
