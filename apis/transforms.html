Transforms endpoint v2

Create and manage transform steps that modify and filter events as they flow through a pipeline. Base URL: https://api.godzilladocs.dev/v2.

Create a transform step

POST /v2/transforms

Name Type Required Description
pipeline_idstringYesID of the pipeline this transform belongs to.
namestringYesHuman-readable transform name, unique within the pipeline.
typestringYesTransform type: filter, map, aggregate, or custom.
configobjectYesType-specific configuration object defining the transform logic.
positionintegerNoOrder in the pipeline's transform chain (0-indexed). Defaults to append at end.
create-transform.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/transforms \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"pipeline_id\": \"pipe_orders_warehouse\",\n    \"name\": \"filter-high-value\",\n    \"type\": \"filter\",\n    \"config\": { \"expression\": \"event.amount > 100\" }\n  }'

List transforms

GET /v2/transforms?pipeline_id={id} — returns all transform steps for a given pipeline, cursor-paginated. See Rate limits & errors for the pagination envelope.

list-transforms.sh bash 
curl https://api.godzilladocs.dev/v2/transforms?pipeline_id=pipe_orders_warehouse \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\"

Transform types

Each transform type requires its own config shape:

  • filter — Boolean expression that drops events failing the condition.
  • map — Field-level transformations: rename, cast, compute derived values.
  • aggregate — Windowed rollups by time or key boundaries.
  • custom — JavaScript-like expressions for complex logic.
Transform order matters

Transforms are executed in the order they appear in the pipeline. Position matters for performance and correctness: place filters early to reduce downstream work, and aggregates before maps when possible.
