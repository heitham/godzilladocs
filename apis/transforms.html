Transforms endpoint v2

Define and manage transforms — the data shaping operations that filter, map, and enrich events as they flow through a pipeline.

Create a transform step

POST /v2/transforms

Name Type Required Description
pipeline_idstringYesID of the pipeline this transform belongs to.
namestringYesHuman-readable transform name, unique within the pipeline.
typestringYesOne of filter, map, enrich, or aggregate.
configobjectYesType-specific configuration: filter expression, mapping rules, or enrichment source.
positionintegerNoOrder in the transform chain (0-indexed). If omitted, appended to the end.
create-transform.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY" \\\n  -H "Content-Type: application/json" \\\n  -d '{\n    "pipeline_id": "pipe_orders_dw",\n    "name": "filter-high-value",\n    "type": "filter",\n    "config": { "expression": "$.amount > 1000" }\n  }'

List transforms in a pipeline

GET /v2/pipelines/{pipeline_id}/transforms — returns the ordered array of transform steps for a pipeline.

list-transforms.sh bash 
curl -X GET https://api.godzilladocs.dev/v2/pipelines/pipe_orders_dw/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY"

Transform ordering and evaluation

Transforms are evaluated left-to-right in the order specified by the position field. Output from one transform feeds into the next. If a filter drops an event, subsequent transforms do not run on it.

Transform composition

Use position when updating a pipeline to reorder steps without recreating them. The system automatically adjusts the chain and validates that the output schema of one step is compatible with the input of the next.

Schema validation

When you add or reorder a transform, the pipeline validates the data flowing through it. If an intermediate step's output does not match the next step's expected input, the pipeline enters a degraded state until fixed.

Transform types

Filter

A filter transform drops events that do not match a condition, using JSONPath expressions. Config requires an expression field with a valid JSONPath selector.

Map

A map transform shapes the event payload by extracting, renaming, or projecting fields. Config specifies field_mappings, an object where keys are the new field names and values are JSONPath expressions selecting from the input event.

Enrich

An enrich transform augments the event with data from an external source (HTTP endpoint or lookup table). Config includes the source_url and optional cache_ttl_seconds.

Aggregate

An aggregate transform groups events by a key and produces summary statistics. Config specifies the group_by_field and aggregations (e.g., count, sum, average).
