Transforming events in flight

In Godzilla, pipelines can apply inline transformations to events in real time between ingestion from a source connector and egress to a destination connector. This guide covers how to configure reshape, filter, and enrich transform steps.

Configuring transforms

Transforms are defined as an ordered array in your pipeline configuration. When creating or updating a pipeline via the Pipelines endpoint, supply the transforms field:

pipeline-transforms.json json 
{
  "name": "orders-etl",
  "source_connector_id": "conn_pg_orders",
  "destination_connector_id": "conn_snowflake_dw",
  "transforms": [
    { "type": "filter", "config": { "field": "payload.status", "operator": "neq", "value": "cancelled" } },
    { "type": "reshape", "config": { "pick": ["order_id", "customer_id", "total_amount"], "rename": { "total_amount": "amount_usd" } } },
    { "type": "enrich", "config": { "add_fields": { "environment": "production", "processed_by": "godzilla-v2" } } }
  ]
}

Reshaping events

The reshape step modifies the structural schema of the event payload. Common reshaping operations include:

  • Field selection: Keep only specified fields with pick or remove sensitive attributes with omit.
  • Renaming: Map source property names to match target destination schemas with rename.
  • Casting and formatting: Coerce string values to numeric types or timestamps into standardized ISO-8601 strings.
reshape-step.json json 
{
  "type": "reshape",
  "config": {
    "pick": ["id", "user_id", "subtotal", "tax"],
    "rename": { "id": "order_id" },
    "cast": { "subtotal": "float", "tax": "float" }
  }
}

Filtering events

The filter step evaluates incoming events against conditional rules. If an event does not meet the predicate, Godzilla drops it from the pipeline immediately without forwarding it to subsequent transforms or destination connectors.

Filtered events vs. errors

Filtered-out events are dropped cleanly by design and do not enter the dead-letter queue. Only unhandled transformation errors or destination delivery failures trigger retries.

Supported comparison operators include eq, neq, gt, gte, lt, lte, in, and contains.

Enriching events

The enrich step adds new context to events as they flow through the pipeline. You can inject static metadata, environment tags, or calculated values derived from other payload fields.

enrich-step.json json 
{
  "type": "enrich",
  "config": {
    "add_fields": {
      "pipeline_version": "2.0",
      "region": "us-east-1"
    }
  }
}

Step ordering and error handling

Transform steps run sequentially in array order. Placing filter steps first reduces processing overhead by eliminating irrelevant records before running heavier reshaping or enrichment operations.

Transform failures

If a transform step throws an unhandled exception (such as parsing malformed JSON or casting incompatible types), the event is retried according to your pipeline's retry policy.
