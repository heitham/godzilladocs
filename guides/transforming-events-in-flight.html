Transforming events in flight

This guide covers reshaping, filtering, and enriching events as they pass through your pipeline — turning raw input into business-ready data.

Why transform?

Raw events from a source often need modification before reaching their destination: flattening nested structures, dropping sensitive fields, adding context from external APIs, or routing based on event content. Transformations let you express this logic declaratively without writing custom code.

Reshaping events

Use projection to select and rename fields from your input events. For example, if a source emits:

{{ds:component/code-block|language=json|code={\n "user_id": 123,\n "first_name": "Alice",\n "last_name": "Smith",\n "internal_rank": "VIP",\n "billing_address": { ... }\n}}}

You can project down to just the fields you need in the destination:

json 
{\n  "id": "$.user_id",\n  "name": "$.first_name + ' ' + $.last_name",\n  "vip": "$.internal_rank == 'VIP'"\n
}

The result:

json 
{\n  "id": 123,\n  "name": "Alice Smith",\n  "vip": true\n
}

Filtering events

Not every event needs to reach your destination. Use filters to drop events that don't meet criteria. Common patterns include:

  • Skip internal events: $.event_type != "internal_debug"
  • Only high-value records: $.order_total > 100
  • Require non-null fields: $.customer_email != null
Filtered events aren't lost
Dropped events are tracked but not written to the destination. You can query them in the pipeline's dead-letter queue if needed.

Enriching events

Add context by looking up data from external sources or databases during the transformation phase. For example, enrich user events with account tier from a customer database:

Transform rule json 
{\n  "user_id": "$.user_id",\n  "email": "$.email",\n  "account_tier": "lookup('customer_db', $.user_id, 'tier')"\n
}
Enrichment adds latency
Each external lookup during transformation slows the pipeline. Use sparingly and consider caching or denormalizing data in the source if latency becomes an issue.

Combining transformations

You can apply reshape, filter, and enrichment rules in sequence. The pipeline evaluates them in order:

  1. Filter out unwanted events
  2. Reshape fields
  3. Enrich with external data
  4. Write to destination

Debugging transformations

When transformations produce unexpected output, use the pipeline's test mode to replay events with verbose logging. You'll see each transformation step and where data might be lost or renamed.
