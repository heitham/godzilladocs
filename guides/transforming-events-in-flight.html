Transforming events in flight

This guide covers reshaping, filtering, and enriching events as they flow through your pipeline — powerful transformations that happen in-flight without additional infrastructure.

Understanding in-flight transformations

Events entering a pipeline often don't match the shape expected by their destination. Godzilla lets you transform events at the pipeline level, before they reach connectors. This keeps your pipeline logic centralized and avoids duplicating transformation logic across services.

Reshaping event structure

Use the map transformation to select, rename, and restructure fields:

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={\n \"transformations\": [\n {\n \"type\": \"map\",\n \"fields\": {\n \"user_id\": \"event.userId\",\n \"action\": \"event.type\",\n \"timestamp\": \"@timestamp\"\n }\n }\n ]\n}}}

The map transformation extracts fields from the source event and assigns them to new names in the output event. Nested paths are supported using dot notation.

Filtering events

Use the filter transformation to pass through only events matching a condition:

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={\n \"transformations\": [\n {\n \"type\": \"filter\",\n \"expression\": \"event.status == 'success'\"\n }\n ]\n}}}

Events that don't match the filter expression are silently dropped and not sent to the destination. This is useful for reducing noise or focusing on specific event types.

Filter semantics

Filtered events are counted separately in pipeline metrics. Check your monitoring dashboard to verify that filtering is working as expected.

Enriching events

Add computed fields to enrich events with derived data:

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={\n \"transformations\": [\n {\n \"type\": \"enrich\",\n \"fields\": {\n \"event_year\": \"year(@timestamp)\",\n \"is_bot\": \"event.userAgent contains 'bot'\",\n \"revenue_usd\": \"event.price * event.quantity\"\n }\n }\n ]\n}}}

Enrichment expressions can use built-in functions like year(), contains(), and arithmetic operators. The enriched fields are added to the event without removing existing ones.

Chaining transformations

Transformations are applied in order — the output of one becomes the input to the next:

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={\n \"transformations\": [\n { \"type\": \"filter\", \"expression\": \"event.status == 'success'\" },\n { \"type\": \"enrich\", \"fields\": { \"processed_at\": \"now()\" } },\n { \"type\": \"map\", \"fields\": { \"id\": \"event.id\", \"ts\": \"event.processed_at\" } }\n ]\n}}}

First, events are filtered to successful ones. Then, a timestamp is added. Finally, the output is reshaped to include only id and ts.

Performance considerations

Transformations run synchronously and can impact pipeline throughput. For heavy lifting, consider:

  • Filtering events as early as possible to reduce downstream work
  • Avoiding expensive expressions inside map transformations
  • Testing transformation performance with realistic event volumes

Troubleshooting

If transformed events don't match your destination schema, check your transformation logic in the pipeline UI and review a sample of raw vs. transformed events in the metrics view. Validation errors are logged with each batch that fails.
