Transforming events in flight

Godzilla pipelines can reshape, filter, and enrich events as they flow from source to destination. Transforms run on every event and allow you to adapt data to your destination's schema, drop unwanted events, and add context from external systems.

Overview

A transform is a function that takes an incoming event and returns zero or more output events. Each output can be shaped differently from the input, and a single input event can produce multiple outputs (or none at all).

Reshaping events

Use field mapping and projection to adapt your source data to a destination schema:

{{ds:component/code-block|filename=example.transform.js|language=javascript|code=module.exports = (event) => { return { order_id: event.id, customer_email: event.user.email, total_amount: event.cart.subtotal + event.cart.tax, timestamp: new Date(event.created_at).toISOString() }; };}}

The returned object becomes the event sent to the destination. Rename fields, compute derived values, and drop unused columns — the destination receives only what you return.

Filtering events

Return null or an empty array to drop an event entirely. Use this to exclude test data, low-value transactions, or events that don't meet your business rules:

{{ds:component/code-block|filename=example.filter.js|language=javascript|code=module.exports = (event) => { // Only forward orders over $100 if (event.total_amount < 100) { return null; // Drop this event } return event; };}}

Returning an empty array also filters out the event. This is useful when you want to make a side effect (like logging or posting to an analytics service) but prevent the event from flowing downstream.

Enriching events

Fetch additional data during transform execution to add context to each event:

{{ds:component/code-block|filename=example.enrich.js|language=javascript|code=const fetch = require('node-fetch'); module.exports = async (event) => { // Look up customer tier from external API const customer = await fetch( `https://api.example.com/customers/${event.customer_id}` ).then(r => r.json()); return { ...event, customer_tier: customer.subscription_tier, lifetime_value: customer.lifetime_value }; };}}
Performance implications

External API calls add latency. Cache responses when possible, and ensure your enrichment service has high availability — slow or down enrichment services will back up your pipeline.

Batching outputs

Return an array to produce multiple events from a single input:

{{ds:component/code-block|filename=example.batch.js|language=javascript|code=module.exports = (event) => { // Split a multi-item order into one event per line item return event.line_items.map(item => ({ order_id: event.id, item_sku: item.sku, quantity: item.quantity, price: item.unit_price })); };}}

This is useful for normalizing denormalized data or creating audit events alongside primary data flow.

Error handling

If a transform throws an error, the event is retried according to your error and retry policy. Validation errors should throw explicitly rather than silently returning null:

{{ds:component/code-block|filename=example.validate.js|language=javascript|code=module.exports = (event) => { if (!event.email || !event.email.includes('@')) { throw new Error('Invalid email: ' + event.email); } return event; };}}

Testing transforms

Write unit tests against your transform functions before deploying them to a pipeline. Test with real event shapes from your source and verify the output schema matches your destination expectations.
