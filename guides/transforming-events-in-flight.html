Transforming events in flight

This guide covers how to reshape, filter, and enrich events as they pass through a pipeline — transforming raw data from your source into the exact shape your destination expects.

Reshaping event structure

A transform extracts fields from the incoming event and maps them to a new output structure. Use transforms to flatten nested data, rename fields, or select only the columns you need.

reshape-transform.json json 
{
  "transform": {
    "type": "jmespath",
    "expression": "{ id: user.id, email: user.contact.email, created: timestamp }"
  }
}

Filtering events

Filter out events that don't meet your criteria — for example, dropping test transactions or skipping events from staging environments. Filtered events are still recorded in the pipeline's audit log but do not reach your destination.

filter-transform.json json 
{
  "transform": {
    "type": "filter",
    "condition": "environment == 'production' && amount > 100"
  }
}
Filtered events are not lost

Filtered events skip the destination write but remain queryable in your pipeline's event history. Use the API to review what was filtered and when.

Enriching events

Add computed fields, lookups from external systems, or metadata to each event before it reaches your destination. Enrichments can call out to external APIs, query a database, or perform calculations on the event data.

enrich-transform.json json 
{
  "transform": {
    "type": "enrich",
    "lookup": {
      "service": "user-api",
      "key_field": "user_id",
      "output_fields": ["tier", "region", "last_login"]
    }
  }
}

Chaining multiple transforms

Transforms run in sequence — the output of one becomes the input to the next. This lets you filter first, reshape second, and enrich last, keeping your logic modular and testable.

Transform performance

Enrichments that call external services add latency. Consider caching results, using batch lookups, or pre-computing enrichments upstream of your pipeline if throughput is critical.

Testing transforms locally

Use the Pipelines endpoint to dry-run a transform against sample events before deploying it to production. This lets you validate your JMESPath expressions and filter conditions without risking live data.
