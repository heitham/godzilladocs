Transforming events in flight

As events flow from a source connector to a destination in a pipeline, you can transform them in real time. Transforms allow you to reshape data structures, discard irrelevant records, and enrich events with additional context before they reach storage or downstream consumers.

How transforms work

Transforms run sequentially in the order defined in the pipeline's transforms array. Each step accepts the output of the previous step, modifies or evaluates the event, and passes the result along to the next step. If all transforms succeed, the resulting event is written to the destination connector.

Reshaping event payloads

Use reshape transforms to rename fields, restructure nested payloads, and prune unnecessary data before writing to the destination.

reshape-transform.json json 
{
  \"type\": \"reshape\",
  \"config\": {
    \"mappings\": {
      \"id\": \"payload.order_id\",
      \"total_price\": \"payload.amount_cents\",
      \"customer_email\": \"payload.customer.email\"
    },
    \"remove\": [\"payload.internal_notes\", \"payload.payment_token\"]
  }
}

Filtering events

Filters drop events that do not match specified criteria. Dropped events are cleanly discarded without causing pipeline errors or halting event processing.

filter-transform.json json 
{
  \"type\": \"filter\",
  \"config\": {
    \"condition\": \"payload.status == 'completed' && payload.amount_cents > 0\"
  }
}

Enriching events

Enrichment steps append metadata, compute derived attributes, or inject environment-specific tags into each event payload as it passes through the pipeline.

enrich-transform.json json 
{
  \"type\": \"enrich\",
  \"config\": {
    \"fields\": {
      \"processed_at\": \"$sys.timestamp\",
      \"environment\": \"production\",
      \"region\": \"us-east-1\"
    }
  }
}

Configuring transforms on a pipeline

Provide the list of transform steps when creating or updating a pipeline via the Pipelines endpoint, or manage individual steps via the Transforms endpoint.

pipeline-with-transforms.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/pipelines \\\n  -H \"Authorization: Bearer $GODZILLA_API_KEY\" \\\n  -H \"Content-Type: application/json\" \\\n  -d '{\n    \"name\": \"orders-etl-pipeline\",\n    \"source_connector_id\": \"conn_pg_orders\",\n    \"destination_connector_id\": \"conn_snowflake_dw\",\n    \"transforms\": [\n      {\n        \"type\": \"filter\",\n        \"config\": { \"condition\": \"payload.amount_cents > 0\" }\n      },\n      {\n        \"type\": \"reshape\",\n        \"config\": { \"mappings\": { \"total\": \"payload.amount_cents\" } }\n      },\n      {\n        \"type\": \"enrich\",\n        \"config\": { \"fields\": { \"env\": \"prod\" } }\n      }\n    ]\n  }'
Handling transform errors

If an event fails a transform step due to unexpected formatting or malformed data, Godzilla retries the event according to your retry policy. If retries are exhausted, the event is routed to the dead-letter queue. See Handling errors & retries for details.
