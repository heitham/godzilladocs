Transforming events in flight

This guide covers how to reshape, filter, and enrich events as they pass through a pipeline.

Reshaping events

Use a transform stage to pick fields from the source event and remap them into the shape your destination expects. The simplest reshapes drop unwanted columns, while more complex ones can flatten nested objects or rename fields to match downstream schemas.

reshape-transform.json json 
{
  "type": "map",
  "fields": {
    "customer_id": "id",
    "order_total": "amount",
    "created_at": "timestamp"
  }
}

Filtering events

Drop events that don't meet your criteria using a filter transform. You might filter out test records, exclude events below a minimum threshold, or only process records from a particular region. Filtered events are discarded silently and do not count against your quota.

filter-transform.json json 
{
  "type": "filter",
  "condition": {
    "field": "status",
    "operator": "equals",
    "value": "completed"
  }
}

Enriching events

Add computed fields or data from external sources to each event. Common enrichments include geocoding from IP addresses, currency conversion, or a lookup from a reference database. Enrichments run synchronously — if they fail or time out, the event is retried according to your pipeline's retry policy.

enrich-transform.json json 
{
  "type": "enrich",
  "lookup_url": "https://geocoding.example.com/lookup",
  "match_field": "ip_address",
  "output_field": "geo_location"
}
Transform order matters

Transforms execute in the order you define them. Filter before reshaping to avoid computing on events you'll discard, and enrich after reshaping so your transform output matches expected enrichment input.

Chaining transforms

Combine multiple reshapes, filters, and enrichments in a single pipeline to build complex event workflows. The output of each transform feeds into the next.
