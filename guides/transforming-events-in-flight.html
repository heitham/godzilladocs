Overview

As events flow through your Godzilla pipeline, you often need to modify them—reshaping their structure, filtering out unwanted records, or enriching them with additional data. This guide covers the three primary transformation patterns and when to use each one.

Reshaping events

Event reshaping transforms the structure or schema of events as they move from source to destination. Common use cases include:

  • Field renaming: Map source field names to destination conventions
  • Flattening nested structures: Convert deeply nested JSON into a flat schema
  • Projecting fields: Select only certain fields from the source event
  • Adding computed fields: Create new fields based on existing data

In Godzilla, you define reshaping rules in your pipeline's transformation step. Each rule maps source paths to destination paths with optional type conversions:

reshaping-example.yaml yaml 
pipeline:
  transforms:
    - name: reshape-orders
      type: map
      rules:
        - source: order_id
          destination: id
        - source: customer.name
          destination: customer_name
        - source: line_items[].sku
          destination: skus
          transform: flatten

Filtering events

Filtering removes events from the pipeline based on conditions you define. Use filtering to:

  • Exclude sensitive data: Remove events containing PII before sending to downstream systems
  • Route by event type: Send only certain event types to specific destinations
  • Reduce volume: Sample high-traffic event streams or skip test/debug events
  • Enforce data quality: Drop incomplete or invalid records

Filtering rules use simple comparison operators and boolean logic:

filtering-example.yaml yaml 
pipeline:
  transforms:
    - name: exclude-test-events
      type: filter
      rules:
        - field: environment
          operator: "!="
          value: test
        - field: order_total
          operator: ">="
          value: 0

Enriching events

Event enrichment adds new data to events from external sources—reference tables, APIs, or lookups. Common enrichment sources include:

  • Reference tables: Join against customer profiles, product catalogs, or geography tables
  • External APIs: Fetch real-time data like current exchange rates or geocoding
  • Pipeline state: Add aggregations or counters from earlier in the pipeline

Enrichment is configured by specifying a lookup key and the source to join against:

enriching-example.yaml yaml 
pipeline:
  transforms:
    - name: enrich-with-customer-tier
      type: enrich
      lookup:
        key: customer_id
        source: customers-table
        fields:
          - customer_tier
          - lifetime_value

Combining transformations

In practice, you'll often chain multiple transformations. A common pattern is: reshape → filter → enrich. For example:

  1. Reshape incoming events to normalize field names and flatten nested structures
  2. Filter out any events missing required fields or exceeding size limits
  3. Enrich the remaining events with customer or product data

Godzilla executes transformations in the order you define them, so plan your pipeline logic accordingly.

Performance considerations

Heads up
Complex transformations and high-cardinality enrichments can impact pipeline throughput. Monitor pipeline latency as you add transformations.
  • Reshape is fast: Local field mapping has minimal overhead; use reshape liberally.
  • Filter is efficient: Filtering is applied before expensive operations like enrichment.
  • Enrich can be slow: External lookups and API calls add latency. Cache reference tables when possible.
