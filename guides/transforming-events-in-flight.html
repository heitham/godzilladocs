Transforming events in flight

Once you've connected a source and destination, you can shape the data flowing between them. This guide covers the three core transformation patterns: reshaping events to match your target schema, filtering to exclude unwanted data, and enriching to add context from external sources.

Reshaping events

The simplest transformation extracts and reorganizes fields from incoming events. Use a reshape step to:

  • Map source fields to destination column names
  • Type-cast values (string to integer, object to JSON)
  • Flatten nested objects or arrays
  • Rename fields that conflict with reserved words

Each reshape rule is a source_path → destination_field mapping. Unmapped fields are dropped by default.

pipeline.config.json json 
{"transforms": [{"type": "reshape", "mappings": {"user.id": "user_id", "user.email": "email", "event_time": "created_at"
]}}}

Filtering events

Not every event should reach your destination. Use filters to keep only the events you care about:

  • Exclude test or debug events before they pollute production data
  • Route events based on type or country to different destinations
  • Drop events that fail validation or have missing required fields

Filters use simple boolean expressions: field == value, field > 100, or field IN (a, b, c).

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={"transforms": [{"type": "filter", "condition": "environment != 'test' AND user_id IS NOT NULL"}]}}}
Filter early

Place filter steps near the beginning of your pipeline to avoid wasted processing on events you'll discard.

Enriching events

Enrich events by joining them with reference data from an external source — typically a database lookup or API call:

  • Look up a customer's plan tier by user_id to route them to the right analytics table
  • Fetch geolocation data from an IP address in the event
  • Add a standardized product category to a SKU field

Enrichments are cached to avoid hammering external sources on every event. Failed lookups can be configured to drop the event or pass it through with a null enrichment field.

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={"transforms": [{"type": "enrich", "source": "postgres_reference", "join_key": "product_id", "lookup_field": "sku", "cache_ttl_seconds": 3600, "fields_to_add": ["category", "vendor"]}]}}}

Chaining transformations

Combine multiple transformations in sequence. The pipeline processes them left to right, so the output of one stage becomes the input to the next:

{{ds:component/code-block|filename=pipeline.config.json|language=json|code={"transforms": [{"type": "filter", "condition": "environment != 'test'"}, {"type": "reshape", "mappings": {"user.id": "user_id"}}, {"type": "enrich", "source": "lookups", "join_key": "user_id"}]}}}

Monitoring transformation health

Watch for transformation failures in the pipeline health dashboard:

  • Filter dropout rate — if you're suddenly filtering 90% of events, check your filter condition for regressions
  • Reshape field errors — unmapped source fields mean your schema changed; add new mappings or adjust downstream expectations
  • Enrichment failures — if your reference data source goes down, events may be dropped or delayed depending on your fallback policy
