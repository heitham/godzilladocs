Transforming events in flight

Once events enter your pipeline, you can reshape them, filter out unwanted records, or add enrichment data from external sources — all before they reach their destination.

Reshaping events

Use a transform to extract, rename, or restructure fields from incoming events. Transforms are JavaScript functions that receive an event and return a modified version of it.

{{ds:component/code-block|filename=transform.js|language=javascript|code=export default function transform(event) { return { user_id: event.customer_id, name: event.first_name + ' ' + event.last_name, email: event.contact_email, created_at: new Date(event.signup_timestamp).toISOString() }; }}}

Return null from a transform to drop an event entirely, or throw an error to send it to the dead-letter queue.

Filtering events

Add a filter condition to your transform to block unwanted records at the source. A filter that returns false discards the event; true passes it through.

filter.js javascript 
export default function filter(event) {
  // Only pass through events from paying customers
  return event.plan_type !== 'free';
}
Filters are fast

Filtering in the pipeline is cheaper than transforming and sending to a destination, then filtering downstream. Apply filters early.

Enriching with external data

Your transform can call out to external APIs or databases to add data to each event. Be mindful of rate limits and latency — every enrichment call adds milliseconds to pipeline throughput.

{{ds:component/code-block|filename=enrich.js|language=javascript|code=export default async function enrich(event) { const response = await fetch(`https://api.example.com/users/${event.user_id}`); const userData = await response.json(); return { ...event, user_tier: userData.tier, account_balance: userData.balance }; }}}
Async transforms add latency

Each external call blocks the pipeline for that event. Use with caution on high-throughput pipelines or consider batching lookups with a scheduled task instead.

Chaining transforms

A single transform stage can run multiple functions in sequence. The output of one becomes the input to the next.

Monitoring transform failures

If a transform throws, the event is retried according to your retry policy. Watch transform error rates in Monitoring & alerts.
