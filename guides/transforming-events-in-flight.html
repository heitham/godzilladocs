Transforming events in flight

This guide covers using transforms to reshape, filter, and enrich events as they flow through a pipeline — allowing you to clean, standardize, and augment data without leaving Godzilla.

Overview

Transforms run on every event that enters your pipeline, after the source connector has read it but before it reaches the destination. You can use transforms to:

  • Reshape event structure — rename fields, flatten nested objects, or split one event into many.
  • Filter events — drop rows that don't match your criteria, ensuring only relevant data reaches the destination.
  • Enrich events — add computed fields, join in reference data, or apply business logic.

Adding a transform to a pipeline

When you create or edit a pipeline, a transforms section sits between the source and destination. Each transform is applied in order — the output of one becomes the input to the next.

Transforms are written as JavaScript functions:

{{ds:component/code-block|filename=example-transform.js|language=javascript|code=(event) => { return { ...event, timestamp: new Date().toISOString(), status: event.code >= 400 ? 'error' : 'ok', }; }}}

Your function receives one event object and must return:

  • An object to pass the transformed event downstream.
  • null or undefined to filter out the event (it will not reach the destination).
  • An array of objects to split one event into many.

Common patterns

Renaming fields

{{ds:component/code-block|filename=rename-fields.js|language=javascript|code=(event) => ({ id: event.user_id, name: event.user_name, email: event.user_email, })}}

Filtering by value

{{ds:component/code-block|filename=filter-events.js|language=javascript|code=(event) => { // Only pass through successful requests if (event.status_code >= 400) { return null; } return event; }}}

Adding computed fields

{{ds:component/code-block|filename=enrich-events.js|language=javascript|code=(event) => ({ ...event, tier: event.spend > 1000 ? 'premium' : 'standard', region_code: event.country.toUpperCase(), processed_at: new Date().toISOString(), })}}

Splitting one event into many

{{ds:component/code-block|filename=split-events.js|language=javascript|code=(event) => { // If an event has multiple items, emit one event per item return event.items.map((item) => ({ order_id: event.id, item_sku: item.sku, item_qty: item.quantity, })); }}}

Error handling

If a transform throws an error, the event is moved to the dead-letter queue and Godzilla attempts to retry it later. Ensure your transforms are robust and handle unexpected data shapes — use optional chaining and defensive checks:

{{ds:component/code-block|filename=defensive-transform.js|language=javascript|code=(event) => ({ ...event, email: event.user?.email ?? 'unknown', tags: Array.isArray(event.tags) ? event.tags : [], })}}

Performance considerations

Transforms run synchronously in the pipeline's event loop, so keep them fast:

  • Avoid complex loops or expensive computations inside a transform.
  • Don't make network calls — use enrichment pipelines or a separate lookup service if you need external data.
  • Keep the output event size reasonable — large transformed objects may slow downstream operations.

Monitoring transforms

Use the pipeline detail view to see how many events passed through each transform, how many were filtered, and how many hit errors. Dead-lettered events are logged with the transform name and error details, making it easy to debug.
