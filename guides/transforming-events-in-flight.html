Transforming events in flight

Transforms are intermediate processing steps applied to events as they travel between a source connector and a destination in a pipeline. You can use transforms to reshape payload structures, filter out unwanted records, and enrich events with additional context.

1. Reshaping events

Use reshape transforms to rename fields, restructure nested objects, or strip sensitive and unneeded keys before writing to downstream storage.

reshape-transform.json json 
{
  "type": "reshape",
  "config": {
    "rename": {
      "customer_email": "email",
      "amt_cents": "amount_cents"
    },
    "drop": ["internal_notes", "raw_ip"]
  }
}

2. Filtering events

Filtering lets you conditionally route or drop events based on payload criteria. Non-matching events are discarded immediately, saving destination throughput and storage.

filter-transform.json json 
{
  "type": "filter",
  "config": {
    "condition": "payload.status == 'completed' && payload.amount_cents > 0"
  }
}
Dropped events

Filtered-out events do not trigger retries or dead-letter queue entries; they are treated as successfully skipped.

3. Enriching events

Enrichment transforms add metadata, computed values, or static contextual fields to the event payload before delivery.

enrich-transform.json json 
{
  "type": "enrich",
  "config": {
    "add_fields": {
      "environment": "production",
      "processed_by": "godzilla-pipeline-v2"
    }
  }
}

Configuring transforms in a pipeline

Transforms are supplied as an ordered array on the pipeline definition. Godzilla executes each transform sequentially for every event.

pipeline-with-transforms.json json 
{
  "name": "orders-with-transforms",
  "source_connector_id": "conn_pg_orders",
  "destination_connector_id": "conn_snowflake_dw",
  "transforms": [
    {
      "type": "filter",
      "config": { "condition": "payload.amount_cents > 0" }
    },
    {
      "type": "reshape",
      "config": { "drop": ["raw_ip"] }
    },
    {
      "type": "enrich",
      "config": { "add_fields": { "region": "us-east" } }
    }
  ]
}
Order of execution matters

Because transforms run sequentially, placing filter steps first avoids unnecessary processing on events that will ultimately be dropped.
