Migration guide (v2 → v3)

v3 is the current API version. v2 will no longer accept requests. This guide covers the key breaking changes between v2 and v3, with focus on the deprecated events endpoint.

v2 is no longer supported

The v2 API has been fully deprecated. All v2 endpoints are now offline. Migrate immediately to avoid service interruptions.

Overview of changes

v3 introduces three major improvements:

  • Unified endpoint paths: All resource endpoints now follow the pattern /v3/{resource}/{id} consistently.
  • Enhanced events support: Event filtering via status (success/failed/pending) instead of type, with clearer replay semantics.
  • Better error responses: Structured error objects with stable code fields and detailed descriptions.

Events endpoint migration

The events endpoint is where most users will notice changes. v3 improves filtering and requires the pipeline ID in the replay path.

Query events

v2:

v2.bash bash 
curl -H "Authorization: Bearer $API_KEY" \\\n  'https://api.godzilladocs.dev/v2/pipelines/pipe_abc123/events?type=order.created&since=2026-08-01T00:00:00Z'

v3:

v3.bash bash 
curl -H "Authorization: Bearer $API_KEY" \\\n  'https://api.godzilladocs.dev/v3/pipelines/pipe_abc123/events?status=success&since=2026-08-01T00:00:00Z'

Key differences:

  • Parameter type is removed — filter by status instead (success, failed, or pending).
  • New until parameter for upper-bound timestamp filtering.
  • New page_size parameter for configurable pagination (1–100, default 20).
  • occurred_at is replaced by since and until for clearer range filtering.

Replay an event

v2:

v2.bash bash 
curl -X POST -H "Authorization: Bearer $API_KEY" \\\n  'https://api.godzilladocs.dev/v2/events/evt_8f2c1a90/replay'

v3:

{{ds:component/code-block|filename=v3.bash|language=bash|code=curl -X POST -H "Authorization: Bearer $API_KEY" \\\n -H "Content-Type: application/json" \\\n -d '{}' \\\n 'https://api.godzilladocs.dev/v3/pipelines/pipe_abc123/events/evt_8f2c1a90/replay'}}

Key differences:

  • Replay path now includes the pipeline ID: /v3/pipelines/{pipeline_id}/events/{event_id}/replay.
  • The endpoint expects a JSON body (can be an empty object {}).
  • v3 returns the replayed event object immediately; v2 had no response body.

Other endpoint changes

All endpoints follow the same pattern updates as events. Base URL moves from /v2/ to /v3/, and paths are consistent.

Pagination

Both v2 and v3 use cursor-based pagination. The only change is the addition of page_size in v3:

pagination.bash bash 
curl -H "Authorization: Bearer $API_KEY" \\\n  'https://api.godzilladocs.dev/v3/pipelines?page_size=50&cursor=eyJvZmZzZXQiOjUwfQ'

Error handling

v3 improves error response structure. Both versions return error objects, but v3 adds a request_id for debugging.

v2 error:

v2-error.json json 
{\n  \"code\": \"PIPELINE_NOT_FOUND\",\n  \"message\": \"Pipeline not found\"\n
}

v3 error:

v3-error.json json 
{\n  \"code\": \"PIPELINE_NOT_FOUND\",\n  \"message\": \"Pipeline with ID 'pipe_xyz' does not exist\",\n  \"request_id\": \"req_a1b2c3d4e5f6\"\n
}

Migration checklist

Before deploying v3 code to production:

  • ☐ Update all /v2/ paths to /v3/.
  • ☐ For events queries: replace type filter with status (success/failed/pending).
  • ☐ For event replay: add the pipeline ID to the path and include a JSON request body.
  • ☐ Add request_id capture in error handlers for better debugging (v3 includes this).
  • ☐ Test pagination with the new page_size parameter if needed.
  • ☐ Update SDKs to v3 versions (see SDKs page for details).
