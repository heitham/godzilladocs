Migration guide (v2 → v3) v2 withdrawn

v3 ships with improved error handling, batch operations, and advanced filtering for both Pipelines and Events endpoints. v2 is no longer available — all integrations must upgrade to v3. This guide covers the changes required.

Urgent: v2 is withdrawn

v2 endpoints are no longer accepting requests as of today. If you are still using v2, your integration is already broken. Migrate immediately using the steps in this guide.

What's new in v3

  • Pipelines: Error handling policies — Configure retry, dead-letter queue (DLQ), or discard behavior per pipeline.
  • Pipelines: Batch operations — Create or update multiple pipelines in a single request.
  • Pipelines: Enhanced filtering — Filter pipelines by state, connector, or tags in list operations.
  • Events: Advanced filtering — Filter by status (success, failed, dead_letter) and date ranges.
  • Events: Batch query — Query events across multiple pipelines with complex filters.
  • Events: Single event retrieval — Get a single event with full processing history.
  • Both: Improved error messages — More actionable error responses with suggested remediation.

Update your base URL

All v3 requests use the new base URL:

v2 → v3 diff 
- https://api.godzilladocs.dev/v2/pipelines
- https://api.godzilladocs.dev/v2/events
+ https://api.godzilladocs.dev/v3/pipelines
+ https://api.godzilladocs.dev/v3/events

Breaking changes

v3 is mostly backwards-compatible with v2 for basic create/list/delete operations on Pipelines. The following are the only breaking changes for Pipelines:

  • error_policy field is now required in pipeline responses (defaults to retry if not set).
  • List operations now include a total_count field for pagination context.

Events endpoint changes: All v2 event list operations have been superseded by improved v3 equivalents with more filter options. Event ID and replay operations are unchanged.

Pipelines: Add error handling policies

v3 introduces structured error handling. When creating or updating a pipeline, specify an error policy:

pipeline-with-error-handling.json json 
{
  "name": "ingest-orders",
  "source_connector_id": "conn_pg_orders",
  "destination_connector_id": "conn_snowflake_dw",
  "error_handling": {
    "policy": "retry",
    "max_attempts": 3,
    "backoff_ms": 1000
  }
}

Supported policies:

  • retry — Retry failed events up to max_attempts times (default).
  • dlq — Write failed events to a dead-letter queue for later inspection.
  • discard — Silently drop failed events (use with caution).

Pipelines: Use batch operations

Create or update multiple pipelines in a single request:

batch-create-pipelines.sh bash 
curl -X POST https://api.godzilladocs.dev/v3/pipelines/batch \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY" \\\n  -H "Content-Type: application/json" \\\n  -d '{\n    "pipelines": [\n      {\n        "name": "ingest-orders",\n        "source_connector_id": "conn_pg_orders",\n        "destination_connector_id": "conn_snowflake_dw"\n      },\n      {\n        "name": "ingest-users",\n        "source_connector_id": "conn_pg_users",\n        "destination_connector_id": "conn_snowflake_dw"\n      }\n    ]\n  }'

Pipelines: Enhanced list filtering

v3 supports filtering on Pipelines list operations:

list-active-pipelines.sh bash 
curl https://api.godzilladocs.dev/v3/pipelines?state=active&connector_id=conn_snowflake_dw \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY"

Events: Advanced filtering

The Events list endpoint now supports filtering by status and date range:

list-failed-events.sh bash 
curl "https://api.godzilladocs.dev/v3/pipelines/{pipeline_id}/events?status=failed&since=2026-08-01T00:00:00Z&until=2026-08-31T23:59:59Z" \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY"

Events: Batch query (new in v3)

Query events across multiple pipelines or with complex filter combinations:

batch-query-events.sh bash 
curl -X POST https://api.godzilladocs.dev/v3/pipelines/events/query \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY" \\\n  -H "Content-Type: application/json" \\\n  -d '{\n    "filters": {\n      "type": "order.created",\n      "status": "failed",\n      "since": "2026-08-01T00:00:00Z"\n    },\n    "limit": 100\n  }'
v2 is no longer available

v2 endpoints have been shutdown entirely. There is no grace period or fallback — all integrations using v2 are broken as of now and must upgrade to v3 immediately.

Questions?

See the v3 Pipelines endpoint docs or v3 Events endpoint docs for the complete API reference, or reach out to support if you need assistance with migration.
