Migration guide (v2 → v3) Required

v2 support has ended. You must migrate to v3 immediately. v3 ships with event retention configuration and compliance-focused query features. The endpoints are straightforward to upgrade.

v2 support withdrawn

v2 of the Events endpoint is no longer supported as of this release. All v2 clients must upgrade to v3 to continue using the platform. Requests to v2 endpoints will be rejected.

What's new in v3

v3 adds critical compliance and observability features:

  • retention_days — Control how long events are kept in each pipeline (1–365 days, default: 30). Allows fine-grained control over data lifecycle and compliance obligations without blanket org-wide policies.
  • retention_until — Every event now includes a transparent retention deadline, letting you query events within compliance windows.
  • until parameter — Query events up to an upper timestamp bound, in addition to the existing since lower bound.

Update client code

This is a required change. Update your base URLs and optionally add retention_days to any pipeline creation requests:

diff diff 
- POST https://api.godzilladocs.dev/v2/pipelines
+ POST https://api.godzilladocs.dev/v3/pipelines

  {
    "name": "ingest-orders",
    "source_connector_id": "conn_pg_orders",
    "destination_connector_id": "conn_snowflake_dw",
+   "retention_days": 90
  }

- GET https://api.godzilladocs.dev/v2/pipelines/backfill-events/events?since=2026-08-01T00:00:00Z
+ GET https://api.godzilladocs.dev/v3/pipelines/backfill-events/events?since=2026-08-01T00:00:00Z&until=2026-08-31T23:59:59Z

- POST https://api.godzilladocs.dev/v2/events/evt_abc123/replay
+ POST https://api.godzilladocs.dev/v3/events/evt_abc123/replay

New compliance features

Per-pipeline retention policies let you handle mixed data classifications in a single workspace:

  • PII pipelines — Set retention_days: 7 to comply with short data minimization windows.
  • Analytics pipelines — Set retention_days: 365 for longer historical context.
  • Audit logs — Set retention_days: 30 to meet standard compliance standards.

v3 enforces retention at the pipeline level, so different data flows can have independent lifespans. Query the retention_until field on events to confirm your compliance window.

Migration timeline

v2 is no longer supported. Upgrade your integrations immediately. All v2 requests will be rejected.

No backward compatibility

Unlike earlier migrations, v3 requires a URL change. There is no v2 compatibility mode in v3. Update all client base URLs from /v2 to /v3.

Migration notes

  • The retention_days default is 30 days, matching the implicit v2 behavior. If v2 pipelines retained events beyond 30 days, set an explicit retention_days value on upgrade.
  • SDK clients must update the base URL — cached v2 URLs will fail. Clear any cached configuration and redeploy.
  • The new until parameter on list events is optional — omit it to get all events from since to present.
  • Every event response now includes retention_until, which you can use for compliance audits and data governance workflows.
