Migration guide (v2 → v3)

v3 of the pipelines endpoint ships with improved error handling, batch operations, and enhanced filtering. This guide covers breaking changes and new capabilities.

What's new in v3

  • Error handling policies — Configure retry, dead-letter queue (DLQ), or discard behavior per pipeline.
  • Batch operations — Create or update multiple pipelines in a single request.
  • Enhanced filtering — Filter pipelines by state, connector, or tags in list operations.
  • Improved error messages — More actionable error responses with suggested remediation.

Update your base URL

All v3 requests use the new base URL:

v2 → v3 diff 
- https://api.godzilladocs.dev/v2/pipelines
+ https://api.godzilladocs.dev/v3/pipelines

Breaking changes

v3 is backwards-compatible with v2 for basic create/list/delete operations. The following are the only breaking changes:

  • error_policy field is now required in pipeline responses (defaults to retry if not set).
  • List operations now include a total_count field for pagination context.

Add error handling policies

v3 introduces structured error handling. When creating or updating a pipeline, specify an error policy:

pipeline-with-error-handling.json json 
{
  "name": "ingest-orders",
  "source_connector_id": "conn_pg_orders",
  "destination_connector_id": "conn_snowflake_dw",
  "error_handling": {
    "policy": "retry",
    "max_attempts": 3,
    "backoff_ms": 1000
  }
}

Supported policies:

  • retry — Retry failed events up to max_attempts times (default).
  • dlq — Write failed events to a dead-letter queue for later inspection.
  • discard — Silently drop failed events (use with caution).

Use batch operations

Create or update multiple pipelines in a single request:

batch-create-pipelines.sh bash 
curl -X POST https://api.godzilladocs.dev/v3/pipelines/batch \
  -H "Authorization: Bearer $GODZILLA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "pipelines": [
      {
        "name": "ingest-orders",
        "source_connector_id": "conn_pg_orders",
        "destination_connector_id": "conn_snowflake_dw"
      },
      {
        "name": "ingest-users",
        "source_connector_id": "conn_pg_users",
        "destination_connector_id": "conn_snowflake_dw"
      }
    ]
  }'

Enhanced list filtering

v3 supports filtering on list operations:

list-active-pipelines.sh bash 
curl https://api.godzilladocs.dev/v3/pipelines?state=active&connector_id=conn_snowflake_dw \
  -H "Authorization: Bearer $GODZILLA_API_KEY"

Rollback to v2

v2 remains available at https://api.godzilladocs.dev/v2. If you encounter issues with v3, you can revert your integration to use v2 endpoints. View v2 documentation.

Questions?

See the v3 Pipelines endpoint docs for the complete API reference, or reach out to support if you need assistance.
