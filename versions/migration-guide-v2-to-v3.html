Migration guide (v2 → v3) v2 withdrawn

v2 has reached end of life and is no longer accepting requests. This guide covers the breaking changes you need to handle to move a v2 integration to v3.

1. Endpoint paths: /pipelines/{id}/events → events are first-class resources

In v2, events were nested under pipelines. v3 promotes events to first-class resources with their own endpoints:

{{ds:component/code-block|filename=diff|language=diff|code=- GET /v2/pipelines/{pipeline_id}/events?cursor=... + GET /v3/events?pipeline_id={pipeline_id}&cursor=...}}

Events are now listed globally but can still be filtered by pipeline ID, type, and occurrence range. See the v3 Events endpoint reference for full details.

2. Replay endpoint consolidation

The replay endpoint path is simplified to work with the new structure:

{{ds:component/code-block|filename=diff|language=diff|code=- POST /v2/events/{id}/replay + POST /v3/events/{id}/replay}}

The request and response bodies remain identical.

3. Pagination and filtering improvements

Query parameters are now more consistent across endpoints:

{{ds:component/code-block|filename=diff|language=diff|code=- GET /v2/pipelines/{pipeline_id}/events?type=order.created&since=2026-08-18T00:00:00Z&cursor=... + GET /v3/events?pipeline_id={pipeline_id}&type=order.created&since=2026-08-18T00:00:00Z&cursor=...}}

All filters are now optional query parameters, giving you more flexibility in listing events.

v2 endpoints are disabled

v2 API endpoints no longer accept requests. If you're seeing 410 Gone responses, that's why — there is no grace-period fallback. Update your integration immediately.
