Migration guide (v2 → v3) v2 withdrawn

v2 reached end of support on 2026-08-21. v3 is now the only supported version. This guide covers the breaking changes you need to handle to move a v2 integration to v3.

1. Events endpoint path

v2 used /v2/pipelines/ paths. v3 uses /v3/pipelines/. Update any hardcoded API endpoints or SDK configuration.

{{ds:component/code-block|filename=diff|language=diff|code=- GET /v2/pipelines/{pipeline_id}/events\\n+ GET /v3/pipelines/{pipeline_id}/events}}

2. Event status filtering (new capability)

v3 adds a new optional status query parameter to filter events by outcome. This improves query efficiency for common use cases like finding failed events.

example bash 
# Find all failed events in the last hour\\nGET /v3/pipelines/pipe_xyz/events?status=failed&since=2026-08-21T08:00:00Z
Name Type Required Description
statusstringNoOne of success, failed, pending. If omitted, all statuses are returned.

3. Replay API changes

v2 only allowed replaying dead-lettered events (those that exhausted retries). v3 allows replaying any event, but removes automatic dead-lettering — you control retry scope.

{{ds:component/code-block|filename=diff|language=diff|code=- POST /v2/events/{id}/replay (dead-lettered only)\\n+ POST /v3/events/{id}/replay (any event, with retry budget)}}

When replaying in v3, the event is queued with a standard retry budget. If it fails again, it enters your configured dead-letter handling, not an automatic backoff.

4. Event object changes

Event objects now include a processed_at timestamp alongside occurred_at to distinguish when the event was originally created versus when it was handled.

event.json json 
{\n  \"id\": \"evt_8f2c1a90\",\n  \"type\": \"order.created\",\n  \"status\": \"success\",\n  \"occurred_at\": \"2026-08-18T09:12:44Z\",\n  \"processed_at\": \"2026-08-18T09:12:45Z\",\n  \"payload\": { \"order_id\": \"ord_4471\" }\n}
\n\n
v2 no longer supported

v2 endpoints no longer accept requests. All v2 API keys and tokens are invalid. Migrate immediately to avoid service disruption.
