Migration guide (v2 → v3) v2 retired

v2 reached end of life on 2026-08-20. This guide covers the changes you need to make to move a v2 integration to v3. The upgrade is straightforward — most code changes are optional as v3 is backwards-compatible in spirit, with additive enhancements.

1. Update endpoint paths

Change all references from /v2/ to /v3/:

{{ds:component/code-block|filename=diff|language=diff|code=- GET /v2/pipelines/{pipeline_id}/events\n+ GET /v3/pipelines/{pipeline_id}/events\n\n- POST /v2/events/{id}/replay\n+ POST /v3/events/{id}/replay}}

2. Handle new response fields (recommended)

v3 event responses include additional fields that provide better visibility into event processing:

{{ds:component/code-block|filename=event-v3.json|language=json|code={\n \"id\": \"evt_8f2c1a90\",\n \"type\": \"order.created\",\n \"status\": \"processed\", // NEW: processing status\n \"occurred_at\": \"2026-08-18T09:12:44Z\",\n \"processed_at\": \"2026-08-18T09:12:45Z\", // NEW: completion timestamp\n \"payload\": { \"order_id\": \"ord_4471\" },\n \"metadata\": { // NEW: retry and source info\n \"retry_count\": 0,\n \"source\": \"webhook\"\n }\n}}}

Your existing code will continue to work — these fields are safe to ignore. However, we recommend updating error handling to check the status field:

{{ds:component/code-block|filename=usage.js|language=javascript|code=// Before: no status visibility\nconst events = await api.getEvents(pipelineId);\n\n// After: check status explicitly\nconst events = await api.getEvents(pipelineId);\nevents.forEach(event => {\n if (event.status === 'dead_lettered') {\n console.log(`Dead-lettered event: ${event.id}`);\n // Decide whether to replay or investigate\n }\n});}}\n\n

3. Leverage new filtering options

v3 introduces status and until query parameters for more targeted queries:

filtering.sh bash 
# Get only failed events in a time range\ncurl \"https://api.godzilladocs.dev/v3/pipelines/pipe_abc/events?status=failed&since=2026-08-20T00:00:00Z&until=2026-08-21T00:00:00Z\" \\\n  -H \"Authorization: Bearer $API_KEY\"\n\n# Get paginated results with custom page size\ncurl \"https://api.godzilladocs.dev/v3/pipelines/pipe_abc/events?limit=50&cursor=eyJvZmZzZXQiOjUwfQ\" \\\n  -H \"Authorization: Bearer $API_KEY\"
\n\n

4. Use the new event details endpoint

v3 adds a new endpoint to fetch full event history including all retry attempts:

{{ds:component/code-block|filename=event-details.sh|language=bash|code=# Get full event with all attempts\ncurl \"https://api.godzilladocs.dev/v3/events/evt_8f2c1a90\" \\\n -H \"Authorization: Bearer $API_KEY\"\n\n# Returns:\n# {\n# \"id\": \"evt_8f2c1a90\",\n# \"type\": \"order.created\",\n# \"status\": \"processed\",\n# \"attempts\": [\n# { \"id\": \"att_abc123\", \"status\": \"success\", \"timestamp\": \"...\" }\n# ]\n# }\n}}\n\n

5. Enhanced replay responses

When replaying dead-lettered events, v3 now returns the new attempt ID and immediate status:

replay-v3.json json 
{\n  \"id\": \"evt_8f2c1a90\",\n  \"status\": \"processing\",        // NEW: immediate status\n  \"attempt_id\": \"att_9d3e2b11\",  // NEW: track the replay attempt\n  \"replayed_at\": \"2026-08-20T14:35:22Z\"\n
}
Timeline

v2 is no longer available. If you see 404 errors on /v2/events/*, migrate to v3 immediately — there is no grace period. See the changelog for the exact retirement date.
