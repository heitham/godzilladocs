Rate limits & errors v2

\n\n
\n
1,000
\n
requests / minute
\n

Default rate limit for standard-tier API keys, per workspace.

\n
\n\n

See also: For complete details on plan tiers, quotas, and what happens when you exceed your limit, refer to Quotas & billing.

\n\n

Rate limit headers

\n

Every response includes X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset. A request over the limit returns 429 Too Many Requests with a Retry-After header.

\n\n

Pagination

\n

List endpoints (Pipelines, Connectors, Events) use cursor-based pagination — a departure from v1's offset-based pagination.

\n\n
\n
\n list-response.json\n json\n \n
\n 
{\n  \"data\": [ { \"id\": \"pl_ingest_orders\" } ],\n  \"next_cursor\": \"eyJvZmZzZXQiOjIwfQ\",\n  \"has_more\": true\n}
\n
\n\n

Error shape

\n
\n
\n error-response.json\n json\n \n
\n 
{\n  \"error\": {\n    \"code\": \"connector_unauthorized\",\n    \"message\": \"The connector's credentials were rejected by the source system.\",\n    \"request_id\": \"req_c93a10\"\n  }\n}
\n
\n\n
\n
Breaking change from v1
\n

v1 returned bare error strings. v2 always wraps errors in an error object with a stable code field — match on code, not on message text.
