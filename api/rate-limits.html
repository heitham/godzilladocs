Rate limits v2/v3

1,000
requests / minute

Default rate limit for standard-tier API keys, per workspace.

429
Status code

Returned when you exceed your rate limit.

60
seconds

Standard rate limit window.

See also: For complete details on plan tiers, quotas, and what happens when you exceed your limit, refer to Quotas & billing.

Rate limits apply to v2 and v3

These rate limits are shared across both v2 and v3 API versions. The Events and Pipelines endpoints are available in both v2 and v3, while other endpoints remain on v2.

Rate limit headers

Every response includes three rate-limit headers:

X-RateLimit-Limit
Request quota

Your rate limit for this window.

X-RateLimit-Remaining
Requests left

Remaining requests in the current window.

X-RateLimit-Reset
Window reset time

Unix timestamp when the limit resets.

A request over the limit returns 429 Too Many Requests with a Retry-After header indicating seconds to wait.

Pagination

List endpoints (Pipelines, Connectors, Events) use cursor-based pagination — a departure from v1's offset-based pagination.

list-response.json json 
{\n  "data": [ { "id": "pl_ingest_orders" } ],\n  "next_cursor": "eyJvZmZzZXQiOjIwfQ",\n  "has_more": true\n}
