Rate limits v2 Stable

\n

API rate limits are enforced per workspace using a 60-second sliding window. Limits apply across all pipelines, connectors, and API keys created within the workspace.

\n\n
\n
100
\n
requests / minute (Developer)
\n

\n
\n\n
\n
1,000
\n
requests / minute (Standard)
\n

Default rate limit for Standard tier API keys per workspace. See Quotas & billing for all plan tiers.

\n
\n\n
\n
10,000+
\n
requests / minute (Enterprise)
\n

Customizable rate limits for Enterprise plans up to 50,000+ req/min.

Rate limit headers

\n

Every response includes X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset. A request over the limit returns 429 Too Many Requests with a Retry-After header.

\n\n\n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n \n
HeaderTypeDescription
X-RateLimit-LimitintegerThe maximum number of requests allowed in the current 60-second sliding window.
X-RateLimit-RemainingintegerThe number of remaining requests permitted within the current window.
X-RateLimit-ResetintegerUnix timestamp (in seconds) indicating when the current sliding rate limit window resets.
Retry-AfterintegerNumber of seconds to wait before retrying when a 429 Too Many Requests response is returned.

Pagination

\n

List endpoints (Pipelines, Connectors, Events) use cursor-based pagination — a departure from v1's offset-based pagination.
