Transforms endpoint v2

Create and manage transform steps that manipulate data flowing through pipelines. Base URL: https://api.godzilladocs.dev/v2.

Create a transform step

POST /v2/pipelines/{pipeline_id}/transforms

Name Type Required Description
namestringYesHuman-readable name for the transform step.
typestringYesType of transformation: filter, map, aggregate, or custom.
configobjectYesType-specific configuration object defining the transformation logic.
orderintegerNoPosition in the transform pipeline (0-indexed). Omit to append at the end.
create-transform.sh bash 
curl -X POST https://api.godzilladocs.dev/v2/pipelines/pipe_orders_123/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY" \\\n  -H "Content-Type: application/json" \\\n  -d '{\n    "name": "filter-large-orders",\n    "type": "filter",\n    "config": { "condition": "amount > 100" }\n  }'

List transform steps

GET /v2/pipelines/{pipeline_id}/transforms — returns all transform steps for a pipeline in order.

list-transforms.sh bash 
curl -X GET https://api.godzilladocs.dev/v2/pipelines/pipe_orders_123/transforms \\\n  -H "Authorization: Bearer $GODZILLA_API_KEY"

Transform execution order

Transform steps execute in the order specified by their order field. Events flow sequentially through each step: output from one step becomes input to the next. If a filter step rejects an event, remaining steps are skipped.

Updating pipeline transforms

Modifying transform steps on an active pipeline applies the changes to newly arriving events only. In-flight events continue through the previous transform configuration. Existing data in the destination is not retroactively transformed.
